# Fooder — дневник питания с умными подсказками

Два слоя:
- **`src/`** — модуль подсказок на TypeScript без зависимостей. Работает локально, без интернета и без ИИ: только правила и история дневника.
- **`app/` + `android/`** — минимальное Android-приложение: веб-интерфейс в оболочке Capacitor. Экраны: дневник со счётчиком и подсказками, добавление продукта, настройки. Данные хранятся только на телефоне.

## Скачать APK

Последняя сборка: https://github.com/vseznamus/Fooder/releases/latest/download/fooder.apk

APK собирается GitHub Actions (`.github/workflows/android.yml`) на каждый пуш в `main` и публикуется в Releases. Чтобы установить, разрешите на телефоне установку из браузера или файлового менеджера.

**Подпись.** Если в секретах репозитория есть `FOODER_KEYSTORE_BASE64` и `FOODER_KEYSTORE_PASSWORD` (alias `fooder`), сборка подписывается постоянным ключом, и новые версии ставятся поверх старых. Без этих секретов каждая сборка подписывается временным ключом: перед установкой новой версии старую придётся удалить, вместе с записями дневника.

```bash
npm run build:web        # веб-часть → www/
npx cap sync android     # копирует www/ в android/
# Затем в Android Studio или: cd android && ./gradlew assembleDebug
```

Чтобы быстро попробовать подсказки, откройте настройки и нажмите «Заполнить примером за 45 дней».

## Где что показывать

| Экран | Блок | Функция |
|---|---|---|
| Главный экран дневника, под счётчиком | «Что добрать сегодня» | `suggestTopUp()` |
| Там же, ниже | Карточка недельного баланса | `weeklyBalance()` |
| Экран добавления продукта, до поиска | «Обычно вы едите» | `usualForMeal()` |
| Там же, после добавления продукта | «Часто вместе с …» | `oftenTogether()` |

```ts
import { suggestTopUp, usualForMeal, oftenTogether, weeklyBalance, dismissProduct, toEntry } from 'food-suggestions';

const r = suggestTopUp({ goals, history, catalog, settings, now: '2026-11-05T18:30' });
if (r.kind === 'ok') {
  r.summary;      // «Осталось 600 ккал, белка не хватает 45 г, жиров почти лимит → нужен белковый продукт с минимумом жиров»
  r.suggestions;  // 3–5 вариантов: «Куриная грудка варёная, 150 г — +45 г белка, 206 ккал, останется 395 ккал»
  r.combos;       // до 3 наборов из 2–3 продуктов, закрывающих остаток почти в ноль
} else if (r.kind === 'over') {
  r.message;      // мягкое сообщение
  r.lowCalorie;   // вода/чай + овощи
}

const u = usualForMeal({ history, catalog, settings, now, alreadyAdded });
u.products;   // продукты с обычной порцией (медиана) → добавить одним касанием через toEntry()
u.templates;  // повторяющиеся наборы: «Банан + Кофе с молоком + Овсянка на воде»

oftenTogether({ history, catalog, settings, now, productIds: ['buckwheat'] }); // → котлета, 2 шт.

// Кнопка «не предлагать это» на любой подсказке:
settings = dismissProduct(settings, suggestion.product.id);
```

Время передаётся локальной строкой `'YYYY-MM-DDTHH:mm'`. Если приём пищи не указан, он определяется по времени: до 11:00 завтрак, до 16:00 обед, до 18:00 перекус, до 23:00 ужин. `catalog` — это `Map<id, Product>`: общая база вместе с продуктами из истории.

## Как это считается

### «Что добрать сегодня» (`src/topUp.ts`)
1. **Остаток** = норма − съеденное сегодня.
2. **Главный дефицит**: макрос с наибольшей долей неза­крытой нормы. У белка приоритет ×1,2, у углеводов ×1, у жиров ×0,9. Если остаток макроса меньше 10 % нормы, макрос помечается «почти лимит».
3. **Кандидаты** сначала берутся из продуктов, съеденных за 60 дней. Общая база добавляется, только если вариантов не хватает.
4. **Порция** выбирается из удобных значений: 50–300 г шагом 50, а для калорийных продуктов 20/30/50/100 г; 1–3 шт., 1–2 стакана; плюс моя обычная порция. Порция обязана укладываться в остаток калорий.
5. **Оценка** (веса в `WEIGHTS`):
   ```
   score = 1.0 · сколько закрыто главного дефицита (0..1)
         − 4   · превышение остатка по другим макросам (в долях нормы)
         − 1   · перебор по главному макросу
         − 0.4 · калорий потрачено больше, чем закрыто дефицита
         + 0.25· как часто я его ем (логарифм)
         + 0.15· подходит к текущему приёму пищи
         − 0.3 · уже ел сегодня
   ```
   Одна порция рассчитывается не больше чем на 40 % дневной нормы. Поэтому утром с пустым дневником модуль предложит 150 г курицы, а не 300 г «на весь день». Вариант, закрывающий меньше 30 % главного дефицита, не показывается.
6. **Комбинации**: полный перебор пар и троек среди 30 лучших кандидатов с отсечением по калориям (около 40 мс). Набор должен закрыть 85–100 % остатка калорий. Ранжирование — по близости к остатку Б/Ж/У с небольшими бонусами: продукты из истории, подходящие к приёму, разные категории. Комбинации строятся только при остатке 150–1000 ккал: целый день тремя продуктами «в ноль» закрывать бессмысленно.
7. **Норма превышена**: еду не предлагаем. Показываем сообщение и до 3 почти бескалорийных вариантов: вода или чай плюс овощи, в первую очередь из моей истории.

### «Обычно вы едите» и связки (`src/usual.ts`)
- Каждый прошлый приём того же типа получает вес: давность (полураспад 21 день) × тип дня (будни/выходные совпали — 1, иначе 0,35) × близость по времени суток (гауссиана, σ = 90 мин). Параметры лежат в `USUAL_TUNING`.
- Шаблоны — одинаковые наборы продуктов, повторявшиеся в приёме хотя бы дважды.
- Порция — медиана по истории: сначала по этому приёму пищи, иначе по всем. Граммы округляются до 5 г, штучные продукты — до целых штук.
- «Часто вместе»: доля приёмов с продуктом X, в которых был и Y. Нужно не меньше 2 совместных появлений и доля не ниже 30 %.

### Недельный баланс (`src/weekly.ts`)
Серия считается по завершённым дням, от вчерашнего назад, максимум 7 дней:
- белка меньше 85 % нормы;
- клетчатки меньше 80 % нормы;
- сахара больше предела.

День, в котором записано меньше половины нормы калорий, считается недозаполненным и прерывает серию. При серии от 3 дней показывается карточка с 2–3 продуктами из моей истории. Для сахара карточка дополнительно называет главный источник и предлагает перекусы с низким содержанием сахара. У карточки есть стабильный `id` — по нему UI может скрыть её на сегодня.

### Настройки (`src/settings.ts`)
- `excludedProductIds` и `excludedCategories` — продукты и категории, которые никогда не предлагаются. Исключения действуют во всех блоках. Шаблон, в котором есть исключённый продукт, не предлагается целиком.
- `dismissProduct()` — кнопка «не предлагать это». `restore()` возвращает продукт или категорию из исключений.
- `enabled: false` отключает все подсказки.

## Тесты (`test/suggestions.test.ts`)
1. **Дефицит белка**: определение фокуса, формат текста, первой идёт курица, а не жирное; история раньше общей базы; штраф «уже ел сегодня».
2. **Превышение калорий**: нет еды, мягкое сообщение, только вода и овощи.
3. **Пустая история**: подсказки из общей базы с порциями «на один приём»; остальные блоки пустые и не падают.
4. **Утро и вечер**: в будни утром — овсянка, вечером — гречка с котлетами, в выходные — сырники; порция равна медиане; «вместе с гречкой» — котлеты; утренний добор отдаёт приоритет завтрачным продуктам.
5. **Исключённый продукт или категория**: не появляется ни в одном блоке; `dismissProduct` не мутирует настройки; выключатель работает.
6. **Комбинация из 2–3 продуктов**: итог ≤ остатка, остаётся меньше 15 %, белок в пределах ±8 г, жиры не выходят за лимит, продукты из истории.

Плюс тесты недельного баланса (серия, короткая серия, недозаполненный день) и порций (шаги, склонение «2 стакана», ограничение для калорийных продуктов).
